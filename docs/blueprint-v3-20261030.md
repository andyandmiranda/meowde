# MEOWDE Final Blueprint v3.0 — 2026-10-30

## 0. 제품 한 줄 정의
MEOWDE는 설명을 오래 읽는 강의 앱이 아니라, **아주 짧게 이해하고 바로 해보며 같은 개념을 여러 번 다시 만나 자연스럽게 독립 해결까지 가는 초보자용 학습 앱**이다.

최우선 사용자 기준은 문해력·독해력·집중력이 낮고 코딩 경험이 거의 없는 학습자다.

---

## 1. 절대 유지할 확정 사항

- 최상위 탭: **홈 / 학습 / 심화 / 함께 / 마이**
- 어떤 과목·어떤 탭에서도 같은 상단/하단 shell 사용
- 기존 학습 기록, 저장 키, 임시 답안, 진도, 기존 고양이 6마리 보존
- 자동 제출, 임의 보상, 학습 기록 초기화 금지
- Python을 UX 기준 과목으로 삼되 6과목 모두 같은 제품 문법 사용
- Production / main 변경은 별도 승인 전 금지

---

## 2. 공통 화면 Shell

### 상단
모든 화면에서 위치와 크기를 동일하게 유지한다.

**[Meowde 로고·이름] [과목 선택] [언어]**

- 과목 변경 시 현재 탭 의미를 유지한다.
  - Linux 함께 → ML 함께
  - Python 심화 → Linux 심화
- 준비 중 과목은 선택 목록에는 보이되 명확히 비활성 표시한다.
- 언어 버튼은 실제 지원 범위를 넘겨 활성화하지 않는다.

### 하단
모든 과목에서 동일한 5탭.

**홈 · 학습 · 심화 · 함께 · 마이**

규칙:
- 위치, 아이콘, 라벨, 높이, 활성 상태 색상 동일
- 최소 터치 영역 44px
- 한 탭 안에서 다른 과목 UX로 점프하지 않음
- 탭 변경만으로 답안을 제출하거나 보상을 지급하지 않음

---

## 3. 5탭 역할

### 홈
목적: 오늘 무엇을 할지 고민하지 않게 한다.

한 화면의 핵심 행동은 1개.
- 이어서 학습
- 오늘의 추천 학습
- 필요 시 작은 보조 정보

금지:
- 긴 통계
- 여러 동급 CTA
- 과목 전체 설명
- 학습 지도 복제

### 학습
목적: 기초 개념을 아주 짧게 배우고 바로 문제로 확인한다.

구조:
1. 단원 지도
2. 레슨 선택
3. 핵심 개념 1개
4. 예제 1개
5. 즉시 문제
6. 짧은 피드백
7. 다음 문제

**한 화면 = 한 가지 생각**

첫 노출 정보:
- 제목
- 핵심 1~2문장
- 코드/예시 1개
- 행동 1개

나머지는 필요할 때만 펼친다.

### 심화
목적: 강의를 더 읽는 곳이 아니라, 같은 개념을 반복하며 도움을 줄여 독립 해결과 응용으로 이동하는 곳.

기본 5회독:
1. **핵심** — 한 문장 + 예제 하나
2. **반복** — 같은 규칙의 짧은 변형 문제
3. **따라 코딩** — 힌트와 구조 제공
4. **혼자 해결** — 힌트 없이 직접 작성
5. **응용** — 새로운 입력·상황·오류에 적용

원칙:
- 회독이 올라갈수록 설명은 줄고 학습자 행동은 늘어난다.
- 한 번 틀리면 같은 난이도 또는 한 단계 쉬운 변형을 추가한다.
- 맞았다고 곧바로 숙달 처리하지 않는다.
- 다음 날/다음 주 복습에서 새 입력으로 재확인한다.

금지:
- '이해' 단계에서 긴 강의문 전체 펼치기
- 학습 목표/선수 개념/평가 기준을 본문 앞에 대량 노출
- 긴 보고서형 콘텐츠

### 함께
현재 출시 범위:
- 과목 문맥을 유지한 초대 링크 / QR
- 이후 실제 스터디 기능은 별도 확정 후 추가

준비되지 않은 실시간 기능을 있는 것처럼 보이지 않는다.

### 마이
목적: 나의 학습 상태를 짧게 확인한다.

우선순위:
1. 현재 진도
2. 복습할 것
3. 최근 학습
4. 설정/캐릭터는 보조

## 4. 정보량 규칙

### 첫 화면
- 본문 최대 2개 짧은 문단
- 한 문단 2~3줄 이내 권장
- 한 카드에서 핵심 메시지 1개
- CTA 1개 우선
- 세부 설명은 details / bottom sheet / 보조 화면

### 문장
- 짧은 문장
- 한 문장에 한 개념
- 전문 용어는 바로 옆에서 쉬운 말로
- "왜 필요한지"보다 "지금 뭘 보면 되는지" 우선

### 코드
- 작은 예제
- 한 번에 새 문법 1개
- 코드와 설명이 멀리 떨어지지 않음

## 5. 타이포·간격

모든 학습 화면은 같은 vertical rhythm을 사용한다.

- 화면 제목: 22–24px / line-height 1.3–1.35
- 카드 제목: 16–18px / 1.4
- 본문: 14–15px / 1.6–1.65
- 보조문: 12–13px / 1.5–1.55
- 카드 내부 간격: 12px 단위
- 카드 간 간격: 12–16px
- 문단 아래: 8–10px
- 코드 블록: 13–14px / 1.6–1.65

같은 역할의 텍스트는 과목이나 탭에 따라 line-height가 달라지지 않는다.

---

## 6. 버튼 규칙

- 버튼 1개 = 행동 1개
- 가장 중요한 행동은 Primary 1개
- 보조 행동은 Secondary / Text action
- 같은 위계의 Primary를 한 화면에 여러 개 두지 않는다.
- 버튼 라벨은 행동형으로 쓴다.
  - 학습 시작
  - 다음 문제
  - 코드 실행
  - 다시 풀기
  - 힌트 보기
- 의미 없는 "확인", "계속" 남발 금지
- 최소 높이 44px, 모바일 권장 48px
- 비활성 버튼에는 이유가 있어야 한다.

---

## 7. 피드백 규칙

오답:
1. 무엇이 틀렸는지
2. 왜 틀렸는지
3. 다음에 무엇을 바꾸면 되는지

첫 피드백은 2~3문장 이내.
정답 코드 전체, 긴 문법 설명, 기술적 Traceback은 기본 접힘.

정답:
- 짧게 이유 확인
- 바로 다음 행동

## 8. 과목 통일 원칙

6과목이 각각 별도 앱처럼 보이면 실패다.

공통:
- shell
- 5탭
- 지도/단원/레슨 계층
- 카드/버튼/피드백
- 학습/심화 난이도 구조
- 저장·재진입 UX

과목별로 달라질 수 있는 것:
- 콘텐츠
- 코드 실행 엔진
- 과제 유형
- 실습 시뮬레이터

### P0 — 구조 안정화
1. canonical shell 단일화

4. Linux를 동일 shell/학습 문법에 맞춤

### P2 — 함께 확장

## 10. QA 통과 기준

화면마다 다음을 확인한다.

- 3초 안에 "무엇을 해야 하는지" 알 수 있는가
- 첫 화면을 읽는 데 20초 이상 걸리지 않는가
- Primary 버튼이 무엇인지 즉시 보이는가
- 같은 역할의 요소가 다른 화면에서도 같은 위치/스타일인가
- 긴 설명이 기본 펼침 상태가 아닌가
- 모바일 360px에서도 줄바꿈과 버튼이 안정적인가
- Back / Refresh / 과목 전환 후 문맥과 답안이 보존되는가
- 기존 저장 키와 학습 기록이 바뀌지 않는가

## 11. 현재 코드에 대한 판단

현재 구현은 기능 단위 패치가 누적되어 다음 문제가 있다.

- Python 학습과 심화가 서로 다른 정보 밀도와 학습 문법을 사용함
- 심화 일부 화면은 여전히 보고서형 긴 설명을 기본 노출함
- CSS 계층이 여러 파일에서 같은 요소를 덮어써 행간과 색상 회귀 위험이 있음
- Python / Linux / ML shell은 통합 중이지만 완전한 단일 컴포넌트 계약은 아님
- Release PR #114가 기능·UX·QA 변경을 너무 많이 동시에 포함하고 있음

따라서 앞으로는 새 기능 추가보다 이 Blueprint를 기준으로 **중복 UI/CSS를 줄이고 canonical shell + canonical learning surface를 먼저 안정화**한다.
