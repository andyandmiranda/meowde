## 5. 단계 전환·중단 규칙 제안

`Proposed → Ready → In progress → Review → Approved for release → Released`

| 전환 | 필요한 조건 | 담당·중단 조건 |
|---|---|---|
| Proposed → Ready | 문제/원하는결과/소유자/허용범위/완료기준/기준SHA/증거/위험/다음행동/결정주체, 현재 승인 범위, 접근·선행조건 확보 | 00이 우선순위, 해당 소유자가 실행 가능성 확인. 담당 없으면 구현하지 않음 |
| Ready → In progress | 최신 main/PR SHA·현재 작업·승인·직전 실행 조회; 기존 작업 없거나 동일 작업의 인수 범위 확인 | 코드 작업 동시 1개, 공유 쓰기 02만. 기존 작업이 있으면 중복 착수하지 않음 |
| In progress → Review | 격리 diff·정확한 SHA·검증 결과·한계·위험·다음행동 제출 | 승인 필요 시 Review에서 대기. 문서 작업 Review를 출시 가능 판정으로 확대하지 않음 |
| Review → Approved for release | 사용자 직접 승인이 최종 SHA·대상/환경·범위·위험·롤백에 연결됨 | CI/QA PASS·침묵·과거 승인만으로 전환하지 않음 |
| Approved for release → Released | 승인 범위 내 병합 시 expected_head_sha 확인, 목표 환경 배포 후 운영 URL에서 필수 흐름 확인 | 02. 실패 시 Released로 표시하지 않고 승인된 복구 범위와 증거를 기록 |

매 실행 기록에는 위 필드와 직전 실행 ID·시각, 현재 단계, 담당, 관찰한 head, 마지막 변경점, 검증표, 다음 한 행동을 넣는다. SHA가 바뀌면 과거 결과는 원래 SHA에 남기고 영향에 맞게 재검증하며, 승인을 자동 승계하지 않는다.

공유 브랜치 갱신은 `expected_sha` 또는 `--force-with-lease=<ref>:<expected-sha>` 등 예상 SHA 검사로 보호한다. 불일치하면 최신 변경을 읽고 충돌을 보고하며 덮어쓰지 않는다. 새 브랜치는 미존재를 전제로 생성하고 기존 브랜치를 재사용할 때도 같은 검사를 한다. PR 본문에는 원자적 잠금이 없으므로 직전 본문·head를 재조회해 변경을 보존하며 작성자 부재를 보장하지 않는다.

같은 입력·환경·원인 후보의 실패를 무한 재시도하지 않는다. 첫 실패를 기록하고 판별 검사/조건 변경/승인된 조치 중 다음 한 행동을 정한다. 조치가 불가하면 필요한 결정을 요청하고 대기한다. Ready가 없으면 기능을 임의 생성하지 않는다. 완료·새 실패·중요 변화·결정 필요만 알리고, 동일 상태의 반복 알림은 생략한다.

**한계:** 이 제안은 분산 잠금·실행 lease·스케줄러 중복 방지 장치를 구현하지 않는다. 채팅 상태/PR 기록의 수동 조회와 예상 SHA 검사는 중복 착수의 완전한 방지가 아니다. 잠금 구현은 별도 제안·승인·검증 대상이다.

## 6. 자동화 주기 제안 — 모두 비활성 제안

기존 일시정지를 유지한다. 이 문서를 병합하더라도 예약 작업이 생성·재개되지 않는다. 본문은 실행 중인 자동화나 24시간 연속 작업을 보장하지 않는다.

| 담당 | 제안 주기(KST) | 실행·종료 조건 |
|---|---|---|
| 00 HQ | 평일 09:00 | 목표·개발·결정 각 1개. 의미 있는 변화/결정 필요가 없으면 조용히 유지 |
| 01 제품·학습 | 주 1회, 새 근거가 있을 때 | 학습 문제 1개 명세. 새 피드백이 없으면 새 가설 문서 양산 없이 대기 |
| 02 구현 | 승인된 Ready 작업이 있을 때 | 기존 작업 1개를 진행. 장기 작업 확인이 필요할 때만 30분; Review/승인 대기/차단 시 반복 중단 |
| 03 QA | 출시 검증 기간에만 1시간마다 변경 확인 | SHA·배포·관련 설정 변경 시 필요한 검사. 같은 조건의 완료 검사를 재실행하지 않음 |
| 04 고객·사업 | 주 1회 | 새 고객근거·적합한 마감 기회 확인. 모집·외부 연락·계약·비용은 별도 직접 승인 |

자동화 활성화·재개는 이번 승인에 포함되지 않는다. 실행 환경·중복 방지·접근·알림·중단 조건을 수동으로 검증하고 별도 사용자의 승인 범위를 확인한 후에만 설정안을 실행할 수 있다.

## 7. 검토·승인 경계

이번 산출물은 제안 문서와 관련 PR 기록이다. 제품 코드·테스트·설정·기존 운영 정책 파일은 수정하지 않았다. main 병합, Production 배포, 권한 변경, 데이터 파괴, 비용·계약·모집·외부 연락, 다른 채팅 전송, 새 접근 링크 생성은 수행하지 않는다.
후속 기록은 이 문서의 관찰 시각과 기준 SHA를 덮어쓰지 말고 새로운 시각·SHA의 대조 결과로 추가한다.
