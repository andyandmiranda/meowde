# 입문자 관찰 실행안

상태: 준비 완료 / 참여자 모집·실행·결과 미확보. 기준일 2026-10-15 KST.

## 문제와 가설

일반 입문자가 과목과 첫 행동을 이해하고, 설명·예시·단계적 힌트를 이용한 뒤 새로운 문제에 같은 원리를 적용할 수 있는지 아직 확인되지 않았다. 첫 레슨 완료와 학습 효과는 다르다.

가설: 짧은 개념→예시→직접 실습→새 문제 적용 흐름은 과목 선택과 재진입의 혼란을 줄이며, 도움을 줄여도 유사 과제 해결을 지원한다.

## 대상·기간·진행

- 탐색적 관찰 약 5명. Linux·Python 수업이나 특정 교재·ZIP을 경험할 필요가 없다. 익숙한 사람의 점검과 구분하여 사전 경험 수준만 기록한다.
- 준비된 Preview로 1회 약 20분, 다음 날 약 5분 재방문. 모집 뒤 첫 주 안에 시행하는 계획이며 확정 일정은 아니다.
- Linux와 Python 중 먼저 수행할 순서를 교차 배정한다. 진행자는 정답·버튼 위치를 먼저 알려주지 않고 “무엇을 하려는지 말해 주세요”라고 요청한다.
- 참여 동의를 얻은 뒤 무작위 참여 코드와 과제 관찰만 기록한다. 이름·이메일·학교·계정 정보·실제 파일·음성·영상은 기본 수집하지 않는다. 연락이나 녹화가 필요하면 목적·별도 동의·보관 방식을 먼저 정한다.
- 제안 보관 기준: 익명 관찰 원자료는 요약 후 30일 이내 삭제. 실제 수집 전에 PO가 대상·안내·보관 방식을 확인한다. 제품 개인정보 정책으로 확정된 사항은 아니다.

## 진행 대본

1. “이 서비스에서 무엇을 배울 수 있을 것 같나요?” 첫 화면에서 Linux 또는 Python을 찾아 시작하게 한다.
2. Linux 첫 폴더 레슨을 완료하도록 한다. 막히면 힌트를 찾을 수 있는지 관찰한다. 오답이 나와도 바로 답을 주지 않는다.
3. 레슨 뒤 선택적 파일 미션에서 새로운 이름의 폴더와 그 안의 빈 파일을 만들게 한다. 제공된 정답 힌트 없이 먼저 시도하고, 필요할 때 단계별 도움을 준다. 첫 레슨이 가르치지 않은 `touch`는 사전에 설명한 뒤 별도로 평가한다.
4. Python 첫 레슨에서 출력 순서를 예측하고 직접 다른 문구를 출력하게 한다. 문구를 바꿔 적용하는 과제를 추가한다. 선택형 정답만으로 이해를 판정하지 않는다.
5. 과목을 바꿨다가 돌아오고, 페이지를 새로 열어 저장된 위치를 찾게 한다.
6. 다음 날 Linux의 다른 폴더 이름 생성과 Python의 두 줄 출력 과제를 다시 제시한다. 먼저 도움 없이 시도하게 하고 지원 필요량을 기록한다.
7. “어떤 부분이 어려웠나요?”, “다시 온다면 무엇을 하려고 올까요?”, “기록이 어디에 저장된다고 생각하나요?”를 묻는다.

## 기록과 사전 판정 기준

| 지표 | 기록 방법 | 이번 탐색의 제안 성공 기준 |
|---|---|---|
| 첫 미션 진입 | 진행자 안내 전 성공 여부·막힌 화면 | 5명 중 4명 이상 |
| 도움 없는 유사 과제 | 새 과제의 실제 결과와 힌트·진행자 도움 | 5명 중 3명 이상. Linux/Python을 별도 기록 |
| 다음 날 재적용 | 과제 결과와 도움 수준 비교 | 5명 중 3명 이상. 방문하지 않은 사람은 실패와 구분 |
| 기록 보존 | 새로고침·과목 이동 전후 위치와 입력 비교 | 관찰된 기록 손실 0건 |
| 오채점·오해 | 정당한 답안 거부, 잘못된 설명, 실제 실행 오인 | 중대한 문제 0건 |

이는 탐색적 통과 기준 제안이며 통계적 교육 효과 검증이 아니다. 시간이 짧거나 보상을 받았다는 사실만으로 학습 효과를 주장하지 않는다. 기록 손실·명백한 오채점·실행 안전 오인이 나오면 모집 확대를 중단하고 수정한다. 2명 이상이 같은 지점에서 진행자 없이는 시작하지 못하면 해당 흐름을 먼저 개선한다.
