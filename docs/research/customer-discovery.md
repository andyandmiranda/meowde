# 고객·사업 검증 실행안

상태: 가설 / 인터뷰·수요·매출 근거 미확보. 기준일 2026-10-15 KST.

## 검증할 가설

우선 고객 후보는 혼자 Linux·Python을 시작했지만 설치·오류·다음 학습 선택에서 자주 멈추는 일반 성인 입문자다. 짧은 실습과 재도전 지원이 실제 반복 문제를 해결하는지 확인한다. 이 고객상이 확정 타깃이라는 뜻은 아니다. 기관 판매·구독·유료 강의·다른 언어 확장은 별도 후보로 남긴다.

## 인터뷰 계획

- 입문 경험이 있는 후보 5~8명과 약 20분씩. 모집 이후 2주 동안 탐색하는 제안이며 외부 연락은 아직 하지 않았다.
- “유료라면 쓰겠어요?”보다 최근 실제 경험을 묻는다: 언제 배우려 했는지, 무엇 때문에 멈췄는지, 어떤 대안을 썼는지, 시간·비용을 실제 얼마나 썼는지, 다시 시작하게 된 계기는 무엇인지.
- 짧은 사용 뒤 “다음 주에 어떤 문제 때문에 다시 열 것 같은지”와 “현재 쓰는 대안에서 무엇이 부족한지”를 묻는다. 친절한 호평·가상의 구매 의향을 실제 구매로 기록하지 않는다.
- 실가격·결제·유료 체험·광고비·보상비는 여기서 도입하지 않는다. 가격을 정하려면 실제 대안과 고객 근거를 별도 확인한다.
- 개인정보·동의·보관 원칙은 [입문자 관찰안](novice-study.md)을 따르며 최소 익명 메모만 남긴다.

## 측정·판정

| 질문 | 필요한 증거 | 다음 행동 기준(제안) |
|---|---|---|
| 반복되는 문제가 있는가? | 최근 구체적 사례, 실패 맥락, 실제 대안 | 5명 이상 중 3명 이상에게 공통 문제가 있으면 해당 문제를 우선 검증 |
| MEOWDE가 문제를 해결하는가? | 새 과제 해결·재도전·재방문 이유 관찰 | 관찰상 학습 흐름이 막히면 기능·마케팅 확대보다 먼저 수정 |
| 지속적으로 쓸 이유가 있는가? | 자발적 재사용과 수행하려는 과제 | 자발적 재방문이 없으면 이유를 조사. 소수 표본으로 유지율을 추정하지 않음 |
| 지불 근거가 있는가? | 대안에 쓴 실제 비용, 구매 결정 기준·주체 | 근거가 모일 때 가격·유료 가치 제안. 매출 예상치는 아직 작성하지 않음 |

2주 뒤 실제 인터뷰가 없으면 “미실행”으로 보고한다. 대화상 호평만 있고 구체적 문제·반복 사용 동기가 없으면 타깃 가설을 재검토한다. 학습을 방해하는 결제 장벽이나 보상 압박은 실험하지 않는다.

## 후속 결정 자료

익명 사례→반복 문제→현재 대안→학습 관찰→제안 가치→불확실성 순으로 정리한다. 시장 규모·경쟁 가격·지원사업·법률은 이 문서에서 주장하지 않았다. 후속 조사에서는 당시 공식 1차 자료와 기준일을 명시한다.

PO 결정 대상은 실제 모집 방식·필요 비용·가격 실험·사업 방향 변경이다. 관련 결과가 나오기 전 수요, 수익성, 지원금 수혜 가능성을 확정하지 않는다.
